## はじめに

複数リポジトリを並行で触る場面が増えてくると、エディタやGUIアプリを行き来するコストが地味に効いてきます。さらにClaudeCodeで複数タスクを並列に走らせたい、というモチベーションも重なり、思い切って開発環境を一段組み直すことにしました。

before / afterは次のとおりです。

**before**

- コード+ターミナル: Cursor
- Git: Sourcetree

**after**

- ターミナル（マルチプレクサ）: cmux
- エディタ: neovim
- ファイラー: yazi
- Git: lazygit
- シェルプロンプト: starship

GUIアプリ前提のワークフローから、ターミナル上でほぼ完結する構成に振り切った形です。この記事では、移行の理由と各ツールの役割、現時点での課題感を整理します。

## なぜ移行したのか

### 複数リポジトリ間の切り替えコストが無視できなくなった

Cursorはエディタとしては申し分ないのですが、リポジトリごとにウィンドウを立ち上げて切り替える運用がボトルネックになってきました。タスクごとにウィンドウを行き来しているうちに、それだけで思考が分断されてしまう感覚があります。

### ClaudeCodeを並列に走らせたかった

ClaudeCodeはターミナル上で動くツールです。複数セッションを並列に動かすなら、エディタ内蔵のターミナルに閉じ込めるより、ターミナルマルチプレクサで自由にペインを切り分けられた方が圧倒的に取り回しが良さそう、というのが移行の決め手でした。

### 一度はNeovimを真面目に触っておきたかった

これは小さい理由ですが、エンジニアとして一度はvim系を腰を据えて使ってみたい、という気持ちもありました。「触ってみたい」と思ったタイミングを逃すと結局触らないまま、というのもよくある話なので、まとめて移行するならここしかないと判断しました。

## 移行後の構成

ここからは各ツールについて、役割・導入方法・基本的な使い方を順に紹介していきます。

### neovim — エディタ

vim操作にはまだ慣れていませんが、「ターミナル内で完結すること」のメリットを優先して採用しました。プラグインを足していけば自分の手に馴染ませていけるはず、と思って育てている最中です。

**導入方法**

公式ページ: [https://neovim.io/](https://neovim.io/)

macOSであればHomebrewで一発です。

```bash
brew install neovim
```

設定ファイル（`~/.config/nvim/init.lua`）にプラグインマネージャ（lazy.nvimなど）を入れてカスタマイズしていく流れになります。

**基本的な使い方**

vim系の基本的な3モードは押さえておく必要があります。

| モード | 役割 |
|--------|------|
| Normal | カーソル移動・コマンド入力（起動直後はこのモード） |
| Insert | 文字入力（`i` キーで遷移） |
| Visual | 範囲選択（`v` キーで遷移） |

最低限ここを覚えるだけで編集はできるので、まずは `hjkl` での移動、`i` で挿入、`Esc` でNormalへ戻る、`:w` で保存、`:q` で終了、を体に叩き込むところからスタートしました。

### yazi — ファイルマネージャ

ターミナル上で動くTUIファイラーです。ディレクトリ移動・プレビュー・ファイル操作がキーボードだけで完結するため、`cd`と`ls`の往復でディレクトリ構造を把握する手間が大幅に減りました。選んだファイルをそのままneovimで開くフローも軽快です。

**導入方法**

公式ページ: [https://yazi-rs.github.io/](https://yazi-rs.github.io/)

```bash
brew install yazi
```

起動コマンドは `yazi` です。シェル統合（カレントディレクトリを終了時にシェル側へ反映する設定）を入れておくと、ファイラー終了後にそのままシェルで作業を続けられて便利です。

**基本的な使い方**

vim系のキーバインドがそのまま使えるので、neovimと並行して覚えられるのも利点です。

| 操作 | キー |
|------|------|
| 上下移動 | `j` / `k` |
| 親ディレクトリへ | `h` |
| ディレクトリへ入る / ファイルを開く | `l` |
| ファイルを開く（外部アプリ） | `Enter` |
| プレビュー | カーソルを合わせるだけで右ペインに表示 |
| 終了 | `q` |

### lazygit — Gitクライアント

Sourcetreeで慣れ親しんだ「視覚的にdiffを確認してステージング、コミット」というフローを、ターミナル上でキーボードだけで再現できます。ハンクごとのステージングやinteractive rebaseもサクサク回せて、GUIに戻る理由がほとんどなくなりました。

**導入方法**

公式ページ: [https://github.com/jesseduffield/lazygit](https://github.com/jesseduffield/lazygit)

```bash
brew install lazygit
```

リポジトリのルートで `lazygit` と叩くだけで起動します。

**基本的な使い方**

主要な操作は1キーで完結するため、覚えるべきキーは多くありません。

| 操作 | キー |
|------|------|
| パネル間の移動 | `Tab` / `Shift+Tab` または矢印キー |
| ファイルをステージ / アンステージ | `Space` |
| すべてステージ | `a` |
| コミット | `c` |
| プッシュ / プル | `P` / `p` |
| diff表示 | 該当ファイルにカーソルを合わせるだけ |
| ヘルプ | `?` |

迷ったら `?` でヘルプを開けるので、最初のうちはこれを見ながら作業すれば十分です。

### starship — シェルプロンプト

Gitブランチや言語バージョンが一目で分かるよう、プロンプトをstarshipに置き換えました。設定ファイル1つで複数シェルに適用できる手軽さもあり、ターミナル中心の生活にしたタイミングと相性が良かったツールです。

**導入方法**

公式ページ: [https://starship.rs/](https://starship.rs/)

```bash
brew install starship
```

その後、利用しているシェルの設定ファイルに初期化コマンドを1行追加します。

```bash
# zshの場合
echo 'eval "$(starship init zsh)"' >> ~/.zshrc
```

```bash
# bashの場合
echo 'eval "$(starship init bash)"' >> ~/.bashrc
```

**基本的な使い方**

導入直後でも十分見やすいプロンプトになります。カスタマイズしたい場合は `~/.config/starship.toml` を編集します。

```toml
# 例: Gitブランチの色を変える
[git_branch]
style = "bold purple"
```

公式サイトに各モジュール（言語バージョン表示、AWSプロファイル、Gitステータスなど）の設定例が揃っているので、必要なものをコピペで足していくのが楽です。

## 実際のワークフローはどう変わったか

たとえばClaudeCodeで2リポジトリを並列に動かすときは、cmuxでペインを4分割して以下のような配置で運用しています。

- 左上: リポジトリAのClaudeCode
- 左下: リポジトリAでlazygit・yaziを使う作業用シェル
- 右上: リポジトリBのClaudeCode
- 右下: リポジトリBの作業用シェル

Cursor時代は「ウィンドウAへ切り替え → ファイルを開く → ウィンドウBへ切り替え」というOSレベルの操作を繰り返していたところが、目線とキーバインドだけで完結するようになりました。並列でタスクを回すときの摩擦が体感で大きく減ったのが、移行して一番嬉しかったポイントです。

## 実際に使ってみての使用感

### 良かったところ

**コンテキストスイッチが減った**

エディタ・git・ファイル操作がすべてターミナル内で完結するので、アプリ間を行き来する回数が激減しました。ClaudeCodeを2セッション並列で回しながら、片方の結果をlazygitで確認、もう片方をyaziで覗く、という動きがひとつのウィンドウ内で済むのは想像以上に快適です。

**TUIツール群でキーバインドの考え方が揃う**

neovim・yaziはvimライクなキーバインド、lazygitもパネル移動と1キー操作が中心で、ツールごとの操作感に統一感があります。1つ覚えると別のツールにも応用が効くので、学習コストが思ったほど積み上がりませんでした。

**ペアプロや画面共有がしやすい**

ターミナルの画面共有はGUIアプリ全体を映すより軽く、相手にも見せたい部分（ペイン）だけを共有しやすい印象です。ClaudeCodeのセッションを誰かに見せたいときにも気軽に画面を出せます。

### 苦戦しているところ

**vim操作の習熟コストはやはりかかる**

`hjkl`や`:w`に指が馴染むまでは、単純な編集にも時間がかかりました。複雑なリファクタリングなど「とにかく早く編集したい」場面では、慣れているCursorをつい起動してしまうことがあります。ここは完全に時間と慣れの問題で、ショートカットを1つずつ覚えながら少しずつ移行している段階です。

**設定ファイルの管理が増える**

`~/.config/nvim/`、`~/.config/yazi/`、`~/.config/starship.toml` のように、ツールごとに設定ファイルが増えていきます。dotfilesリポジトリで一元管理する仕組みを作っておかないと、別マシンでの再現や見直しが面倒になりそうだと感じています。

**TUIツールごとの細かい挙動差**

たとえばコピー＆ペーストの挙動はターミナルエミュレータとTUIツールの組み合わせで微妙に変わります。最初の数日はクリップボード周りで詰まることが多かったので、ここは設定で整える前提で構えておくのが安全です。

## 今後改善したいこと

### Cursorを完全に外したい

現状はvim操作に不慣れな部分の保険としてCursorを残しています。neovimへの習熟が進めば、最終的にはCursorはアンインストールして、開発環境をもう一段スッキリさせたいところです。

### cmuxをもっと使いこなす

cmuxはキーバインドやレイアウトをかなり細かくカスタマイズできるはずですが、現状はほぼデフォルトに近い状態で使っています。よく使うペイン構成をセッションとして保存する、ペイン移動のキーマップを自分用に最適化するなど、伸び代はまだまだあります。

## まとめ

GUIエディタ中心の構成からターミナル中心の構成へ振り切ったことで、複数リポジトリ・複数セッションを扱うときの心理的負荷がだいぶ下がりました。特にClaudeCodeを並列で回したい人にとっては、ターミナルマルチプレクサベースの開発環境はかなり相性が良いと感じています。

最初はvim操作の壁に戸惑うかもしれませんが、小さなツールを組み合わせて自分の使い方にチューニングしていける楽しさは、GUIツール中心の構成では得にくいものです。気になっているツールがあれば、まずは1つだけでも置き換えてみるところから始めてみてはいかがでしょうか。
